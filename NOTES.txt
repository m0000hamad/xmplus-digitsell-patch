Fix: reserving a plan while the account still had a running subscription was refused by the encoded checkout with the "active subscription" message, because the reserve order carried disableactive=0. The reserve order now sends disableactive=1 - the same flag every customer top-up flow on this panel sends ("add data" dashboard.tpl:751, "add time" dashboard.tpl:971, wallet charge wallet.tpl:794). The checkout requires it whenever the account has an active plan, and it is ignored for a type-1 top-up, so the plan the customer is on is not cancelled. The "cancel my plan" switch is only hidden in reserve mode now, its state left untouched. Manifest and VERSION to 1.24.1.
