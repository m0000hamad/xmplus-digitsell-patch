Fix: the dedicated bot's callbacks spun forever because the webhook never reached the panel - Telegram's servers cannot get through the CDN to xmplus-patch.php, so answerCallbackQuery never ran. The dedicated bot now uses polling by default: bin/c2c.php pulls getUpdates each minute (after clearing any webhook once), verifies the signed callback and the admin chat, applies the decision through the same c2c.decide endpoint the URL buttons use (so the grant logic cannot drift), answers the callback, and edits the message with the outcome and no buttons. Only outbound access to Telegram is needed, which the panel already has for sending messages. A tap is applied within a minute; the client spinner may stop before the toast arrives, but the message itself updates to "تایید شد" / "رد شد". Webhook mode is still available in Settings -> Card to card -> How approvals are received, for a host Telegram can reach.
