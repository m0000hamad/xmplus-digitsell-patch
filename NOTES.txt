Fix 1 - reserve orders: the panel can delete a minted top-up package between the checkout and the approval, so approving a reserved plan failed with "the package behind this order is gone". A reserve is now recognised through plan_reserve (which holds the minted package id) instead of the package row; the reservation is linked to the order and marked paid, and the grant is deferred to the reserve job, which needs the package no more than the reservation does. A normal top-up or subscription whose package really is gone still fails with a clear message instead of silently granting nothing.

Fix 2 - one-tap Telegram decision: the approve/reject buttons in the admin message now perform the action immediately (the one-time token in the link is the whole credential) and show a one-line outcome, instead of opening a confirmation form and waiting for a second tap.
