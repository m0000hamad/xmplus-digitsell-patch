A traffic top-up can now be limited to chosen subscription plans, the way a
time plan already could.

The plan form shows the same picker when the type is set to traffic; leaving it
empty keeps the top-up open to everyone, which is what every existing one is.
A customer only sees the top-ups their current plan is on, both in the "add
data" list and in whether the button appears at all.

This could not ride in the package row: a top-up is saved through the encoded
/admin/plan/save, which rewrites order_note on every save and would wipe it. So
the scope lives in one settings row, timeplan_topup_scope, written by the page
right after the package itself is saved. On a new package the encoded save does
not report the id, so the row is found by name.
