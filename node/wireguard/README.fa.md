# نود WireGuard دیجیتسل

سرور WireGuard را به پنل XMPlus وصل می‌کند تا مصرفش از همان اشتراک مشتری کم شود:
از حجم بسته‌اش، در حالت کیف پول از موجودی‌اش، در نمودارها و گزارش‌ها دیده می‌شود، و
با تمام شدن بسته یا حجم قطع می‌شود.

همان الگوی نود OpenVPN در `node/openvpn`، و سمت پنل همان کد است
(`app/Patch/Vpn.php`). سه تفاوت:

- **لاگینی در کار نیست.** کاربر یک فایل `.conf` می‌گیرد که از کلید خودش ساخته
  شده، و از آن به بعد agent هر peer را هر طور که پنل بگوید اضافه یا حذف می‌کند.
- **فقط یک پورت.** WireGuard یک سوکت بیشتر ندارد، پس باید در فایروال باز باشد و
  همان چیزی است که کاربران به آن وصل می‌شوند. چیزی هدایت نمی‌شود و اسکن پورت هم
  نیست.
- **عبور مستقیم سمت همین سرور انجام می‌شود.** آی‌پی‌های ایرانی و مقصدهای دلخواه مدیر
  از یک ipset و دو قانون iptables مستقیم از سرور بیرون می‌روند. برای همین فایل
  کاربر هیچ خط مسیری ندارد و روی هر برنامه‌ای کار می‌کند — همان چیزی که نود
  OpenVPN با خط‌های `route … net_gateway` دور می‌زد.

## نصب

اول سرور را در پنل بسازید (**سرورها ← سرورهای WireGuard**)؛ شماره‌ی نود و کلید را
می‌دهد و همین دستور را آماده‌ی کپی نشان می‌دهد:

```bash
sudo bash install.sh --panel https://panel.example.com --node 1 --key <key> \
     [--listen auto|443] [--host vpn.example.com] [--dns "1.1.1.1 8.8.8.8"] \
     [--interface wg0] [--mtu 1420]
```

اوبونتو ۲۰.۰۴ به بالا / دبیان ۱۱ به بالا. اجرای دوباره بی‌خطر است: جفت‌کلید سرور
می‌ماند، پس فایل‌هایی که کاربران قبلاً گرفته‌اند به کار می‌مانند؛ تنظیمات و کلید دوباره
نوشته می‌شوند، که همین راه گذاشتن کلید جدید است.

`--listen auto` پورت نصب قبلی را نگه می‌دارد، وگرنه ۵۱۸۲۰، وگرنه اولین پورت آزاد
بالای آن. برای عوض‌کردن پورت باید همین دستور را با `--listen` تازه اجرا کنید؛ پنل
بعداً پورتی را که سرور گزارش کرده نشان می‌دهد.

این اسکریپت فایروال را باز نمی‌کند — قانونش را چاپ می‌کند:

```bash
iptables -I INPUT -p udp --dport 443 -j ACCEPT
```

پورت را نزد ارائه‌دهنده هم باز کنید، وگرنه کاربران وصل نمی‌شوند.

## چه چیزی روی سرور می‌ماند

```
/etc/digitsell-wg/agent.json          تنظیمات agent (فقط root)
/etc/digitsell-wg/server.key          کلید خصوصی سرور (فقط root)
/etc/wireguard/wg0.conf               اینترفیس
/usr/local/lib/digitsell-wg/wg-agent.py
/usr/local/sbin/digitsell-wg-agent    سمبلیک، سرویس‌ها آن را اجرا می‌کنند
digitsell-wg-bypass.service           مارک مسیریابی، جدول و ipset
digitsell-wg-agent.service            هر دقیقه گزارش به پنل
```

## دیدن اینکه کار می‌کند

```bash
wg show wg0                       # peerها، آدرس‌ها و شمارنده‌ها
journalctl -u digitsell-wg-agent -f
ipset list ds-bypass | head       # فهرست عبور مستقیم
ip rule show                      # جدول ترافیک مارک‌خورده
```

عبور مستقیم واقعاً از تونل بیرون است: یک آی‌پی از فهرست بردارید، مسیرش همان
می‌ماند.

```bash
ipset test ds-bypass 5.61.23.100   # برای آی‌پی فهرست true می‌دهد
ip route get 5.61.23.100          # برایش "table 51820" نمی‌آید
```

## حذف

```bash
sudo bash uninstall.sh [--purge]
```

agent، اینترفیس، سرویس‌ها، ipset و قوانین مسیریابی را برمی‌دارد. `--purge`
پکیج `wireguard-tools` و جفت‌کلید سرور را هم پاک می‌کند؛ بدون آن کلید می‌ماند، پس
نصب بعدی همان کلید را می‌دهد و فایل‌هایی که کاربران گرفته‌اند به کار می‌مانند. سرور را
از پنل هم حذف کنید — مصرف ثبت‌شده در هر دو حالت می‌ماند.

## وقتی کار نمی‌کند

**پنل سرور را «در انتظار» نشان می‌دهد.** هنوز agent گزارش نداده. به
`journalctl -u digitsell-wg-agent` نگاه کنید؛ هر دقیقه گزارش می‌دهد و اولین
hello فوری است.

**کاربر وصل می‌شود ولی چیزی کم نمی‌شود.** ممکن است agent بالا باشد ولی push شکست
بخورد. دنبال `push failed:` در لاگ بگردید — پنل رد کرده و همان خط می‌گوید چرا.

**فایل کاربر وصل نمی‌شود.** مقدار `Endpoint` داخل فایل را با
`wg show wg0 listen-port` بسنجید و مطمئن شوید پورت در فایروال باز است.

**پنل فایل را نشان می‌دهد ولی دانلود شکست می‌خورد.** پنل برای ساختن کلید عمومی هر
کاربر به افزونه‌ی sodium نیاز دارد. روی PHP پنل: `php -m | grep -i sodium`. بدون
آن، کارت ادمین همین را بالای صفحه می‌گوید.
